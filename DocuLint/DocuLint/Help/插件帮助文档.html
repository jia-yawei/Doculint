安装

运行环境

  • Microsoft Word 桌面版。
  • .NET Framework 4.7.2 或更高版本，已安装 .NET Framework 4.8 的电脑满足要求。
  • Microsoft Visual Studio 2010 Tools for Office Runtime。
  • Win7 内网电脑如果无法验证安装包发布者，通常需要先补 SHA-2 和根证书相关系统更新。

安装步骤

  1. 关闭所有 Word 窗口。
  2. 运行发布包中的 setup.exe。
  3. 如果提示安装 .NET Framework 或 VSTO Runtime，按提示完成安装。
  4. 重新打开 Word，功能区中出现 搞快点 选项卡即表示加载成功。
  5. 点击 关于 - 版本号 可以查看当前版本和更新记录。
安装或升级前建议关闭 Word。对重要文档执行批量处理前，请先备份原文件。

卸载

  1. 关闭所有 Word 窗口。
  2. 打开 Windows 控制面板 - 程序和功能。
  3. 找到 搞快点 或 DocuLint 相关项。
  4. 点击卸载并按提示完成。
  5. 重新打开 Word，确认功能区中不再显示 搞快点 选项卡。

插件被禁用时的处理

  1. 打开 Word，进入 文件 - 选项 - 加载项。
  2. 在底部“管理”中选择 禁用的项目，点击“转到”。
  3. 如果看到本插件，选择后点击启用。
  4. 再到 COM 加载项 中确认插件已勾选。
  5. 重启 Word。

插件介绍

搞快点 是一个 Word VSTO 插件，重点解决长文档编写时重复、易错、低效的问题。

它主要面向以下场景：

  • 软件需求规格说明、软件设计说明、测试说明、研制总结等软件文档。
  • 需要大量图片题注、表格题注、交叉引用和续表的技术文档。
  • 需要统一样式、大纲级别、多级列表章节号的规范化文档。
  • 需要检查章节标题、题注连续性、列表连续性、未更新域和样式一致性的长文档。
  • 需要从需求文档和设计文档中提取需求标识，并建立追踪关系的文档。
插件尽量复用 Word 原生能力，例如格式刷、编号列表、拆分表格、字段和交叉引用。这样可以减少重复造轮子，也更符合 Word 用户已有操作习惯。

基础使用提示

  • 鼠标悬浮在按钮上，Word 会显示按钮名称和简要提示。部分功能为了提高启动速度，只保留了必要提示。
  • 涉及批量替换、清理手工编号、清理空白页、更新章节号等操作时，建议先保存或备份文档。
  • 右侧窗格中的列表通常支持单击跳转到文档对应位置。
  • 软件专用分组只在文件名包含“软件”时可用，用于减少普通文档误操作。
  • 如果某个功能执行时间较长，可以按 Esc 请求停止后续执行；是否立即停止取决于当前功能是否已接入可取消检查点。

场景用法

场景一：新建或整理一份长文档

  1. 先保存文档，避免后续批量操作无法恢复。
  2. 使用 大纲级别 设置标题层级，正文段落设置为正文。
  3. 如需统一样式，使用 创建自定义样式 创建通用标题和正文样式。
  4. 确保同一级大纲标题使用一致的标题样式。
  5. 章节号异常时，点击 章节号修复 检查并修复。
  6. 插入目录后，最终点击 更新 - 更新目录。

场景二：处理图片、表格和交叉引用

  1. 在图片下方点击 插入图片题注。
  2. 在表格上方点击 插入表格题注。
  3. 正文需要引用图表时，点击 引用题注 或从下拉菜单选择引用方式。
  4. 新增、删除或调整图表后，点击 更新 - 更新题注。
  5. 如果有跨页表格，先把光标放在需要拆分的位置，点击 拆分表格。
  6. 使用 题注窗格 检查图注和表注是否完整。

场景三：交付前检查文档

  1. 勾选 章节标题为空、题注连续性、多级列表连续性、样式一致性、未更新域 中需要检查的项目。
  2. 点击 开始检查。
  3. 在右侧检查结果窗格中逐条查看问题。
  4. 单击检查结果，跳转到文档对应位置修改。
  5. 修改完成后再次检查，直到无关键问题。

场景四：需求提取

  1. 打开名称包含“软件”的文档。
  2. 点击 需求提取 打开右侧窗格。
  3. 点击 提取标识，插件会提取需求标识并跳转到第一个标识位置。
  4. 选中需求名称，点击浮动 添加 按钮，或开启 批量提取 后选中文字自动添加。
  5. 插件会填入需求名称和章节号，并跳转到下一个需求标识。
  6. 点击 保存，把提取结果保存到当前文档。
  7. 需要输出时，点击 导出追踪表，把表格插入光标位置。

场景五：需求追踪

  1. 先在参与追踪的文档中完成需求提取并保存。
  2. 打开保存追踪关系的文档，点击 需求追踪。
  3. 选择 SRS ↔ SDS、SDS ↔ SDD 或 自定义 模板。
  4. 按模板需要导入互追文档，然后在左侧选择源需求，在右侧勾选目标需求。
  5. 需要从相反方向检查时点击 反向追踪，已有关系不会被删除。
  6. 逐条完成映射后，点击 导出追踪表。
一条左侧需求可以追踪多条右侧需求；没有追踪关系的左侧需求导出时右侧留空。

需求追踪详细说明

使用前准备

  1. 在需求文档或设计文档中打开 需求提取，加载需要参与追踪的标识。
  2. 核对标识顺序、名称和章节号。名称和章节号可以直接双击单元格修改。
  3. 保存提取结果。需求追踪读取的是文档中已保存的提取数据，不会临时重新扫描全文。
  4. 若启用标识过滤，可输入最多三种标识，例如 SRS SDS SDD，多个标识之间使用空格分隔。
追踪前应先保存需求提取结果。只在提取列表中看到内容但没有保存，追踪控制台可能无法读取到最新数据。

追踪模板

模板文档方式默认方向导入互追文档
SRS ↔ SDS通常为需求文档与设计文档两份文档左侧 SRS，右侧 SDS需要。插件会根据已保存标识识别哪份文档包含 SRS、哪份包含 SDS。
SDS ↔ SDD同一份设计文档左侧 SDS，右侧 SDD不需要。两类标识都从当前设计文档读取。
自定义当前文档与另一份文档由左表头和右表头定义需要。可手动输入两侧表头名称。

建立和查看追踪关系

  1. 在左侧源需求区选择一条需求。可以使用 上一条、下一条 和 下一条未追踪 快速移动。
  2. 右侧 候选推荐 根据需求名称相似度列出可能目标；详细需求列表 按需求提取时的原始顺序显示全部目标。
  3. 在右侧目标需求前勾选复选框即可建立关系，取消勾选即可移除该关系。一条源需求可以对应多条目标需求。
  4. 状态筛选可以查看全部、已追踪或未追踪需求；名称搜索用于缩小目标列表。
  5. 追踪关系在勾选变化后自动保存到源文档，不需要额外点击保存按钮。

反向追踪

点击 反向追踪 后，左右两侧的文档、标识类型和表头会互换。例如 SRS → SDS 会显示为 SDS → SRS。此操作只是改变查看和编辑方向，已有追踪关系不会被清除；再次点击 恢复正向 可回到默认方向。

精简视图与完整标识

控制台默认显示完整标识。点击 精简视图 后，追踪区域仅显示从标识类型开始的短形式，例如 Q2420-2016-CSCI-SDS-0001 显示为 SDS-0001。再次点击 详细视图 可恢复完整显示。

精简视图只改变屏幕显示。追踪关系保存和导出追踪表始终使用完整标识。

清空与导出

  • 清空追踪关系 只清除当前选中模板下的全部关系，其他模板保存的关系不受影响。
  • 导出追踪表 会在当前 Word 光标位置插入追踪表，并使用完整标识、需求名称和章节号。
  • 同一源需求对应多条目标需求时，导出表会合并源需求单元格；没有目标关系的源需求仍会保留，目标列为空。

互追文档导入说明

导入互追文档时，插件会在后台以只读方式加载其中已保存的需求提取数据，读取完成后立即关闭，不会把导入文档作为可见窗口长期打开。导入文件名过长时，界面会显示省略号，鼠标悬停可查看完整名称。

建议工作流

普通长文档

  1. 保存文档。
  2. 设置大纲级别和样式。
  3. 插入图片题注、表格题注和交叉引用。
  4. 处理跨页表格和图片行距。
  5. 更新目录、总页码和题注。
  6. 执行文档检查。
  7. 修复问题后再次检查。

软件需求规格说明

  1. 整理标题层级，确保导航窗格能正确显示章节。
  2. 使用软件文档检查确认关键章节存在。
  3. 使用需求提取获取需求标识。
  4. 逐条补充需求名称和章节号。
  5. 保存提取结果。
  6. 需要时导出需求表或进入需求追踪。

软件设计说明

  1. 先完成章节和样式整理。
  2. 提取 SDS、SDD 等设计标识。
  3. 导入需求规格说明中的需求提取结果。
  4. 按追踪模板建立 SRS、SDS、SDD 之间的映射。
  5. 导出追踪表并检查空缺项。

常见问题

打开 Word 后没有插件

先检查 Word 加载项是否被禁用，再确认 .NET Framework 和 VSTO Runtime 是否安装完整。

软件专用按钮是灰色

当前文件名需要包含“软件”两个字。插件用这个规则减少普通文档中误触软件专用功能。

标题没有出现在 Word 导航窗格

通常是段落大纲级别仍是正文。把光标放到该段落，使用 大纲级别 下拉框设置为对应级别。

章节号更新后不符合预期

先检查标题是否设置了正确大纲级别，并确认同一级标题使用一致样式。再执行 章节号修复 查看具体异常和修复结果。

需求追踪中没有显示已提取的需求

先回到对应文档的需求提取窗格确认已经保存。追踪控制台读取文档内保存的数据；如果提取后未保存、打开了错误文档或模板与标识类型不匹配，列表可能为空。

反向追踪后原有关系是否会丢失

不会。反向追踪只交换左右显示方向，保存时仍按模板的统一方向存储关系。

交叉引用显示“错误！未找到引用源”

勾选 未更新域 并点击 开始检查，在右侧结果窗格中定位问题位置。修复后更新题注或更新 Word 域。

第一次切换到插件选项卡不够快

插件包含较多按钮、下拉控件和 Office 图标，第一次显示时 Word 需要加载并布局这些控件。当前版本已尽量减少启动和首次切换时的文档扫描。
