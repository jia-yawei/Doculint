# 文档不加班 双宿主架构改造说明

## 已完成改造

### 1. 拆分共享层

- `DocuLint.Host.Abstractions`：定义宿主交互接口与共享模型。
- `DocuLint.Core`：封装可复用业务逻辑（当前已迁移批注列表预览构建逻辑）。

### 2. 保留并接入 Word 宿主

- 现有 文档不加班（Word VSTO）工程已新增对共享层工程引用。
- `ThisAddIn` 中的批注列表构建流程改为：
  - 先通过 `WordDocumentHostAdapter` 抽取批注数据；
  - 再调用 `DocuLint.Core` 的 `CommentPaneEntryBuilder` 生成展示内容。

### 3. 新增 WPS 宿主工程骨架

- 新增 `DocuLint.WpsAddin` 工程。
- 提供 COM 可见的 `WpsAddinBootstrap` 以及基础注册逻辑（HKCU）。
- 当前为最小可编译骨架，后续需要按实际 WPS API 完成生命周期和 UI 接入。

### 4. 更新解决方案

- `DocuLint.slnx` 已纳入：
  - `DocuLint.Host.Abstractions`
  - `DocuLint.Core`
  - `DocuLint.WpsAddin`

## 接下来建议按此顺序推进

1. 在 `DocuLint.Host.Abstractions` 扩展文档能力接口：段落、表格、图片、样式、批注写入。
2. 逐步把 `Ribbon1` 中可纯算法化逻辑迁入 `DocuLint.Core`。
3. 在 `DocuLint.WpsAddin` 实现与 WPS 实际对象模型绑定的适配器。
4. 让 Word/WPS 按钮事件都调用同一套 Core 服务。
5. 增加 Word/WPS 对比回归样例文档，做结果一致性检查。

## 构建说明

- 共享工程（Core/Abstractions/WpsAddin）可使用 `dotnet build` 验证。
- Word VSTO 工程请在 Visual Studio 中构建，或使用 .NET Framework 版 MSBuild；
  `dotnet build` 会因 `ResolveComReference` 机制报错（MSB4803），属于工具链限制。
