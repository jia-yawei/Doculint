# DocuLint 插件需求说明书

## 1. 文档说明

- 文档名称：DocuLint 插件需求说明书
- 编写依据：当前仓库截至 2026-05-07 的已实现功能
- 文档目的：将当前代码中已经落地的用户可见功能整理为一份可直接用于汇报、验收和后续迭代的需求说明
- 当前状态：以现有实现反向整理为主，同时补充已明确的后续规划项；其中 GJB438C 合规检查属于规划能力，当前版本尚未实现

## 2. 产品定位与范围

DocuLint 是一款面向规范化文档编制场景的 Office 插件，当前主交付形态为 Word VSTO 插件。插件围绕“文档编制效率、图表规范、题注维护、批量处理、导航定位、需求追踪、标准符合性检查”七类问题提供辅助能力。

插件的总体设计思路强调“引导式规范”：

- 先帮助用户完成建档、定位和结构统一
- 再处理表格、图片、题注等高频规范对象
- 最后进入追踪、审查和标准符合性检查

当前版本范围如下：

- 纳入范围：Word VSTO 主插件中已挂接到 Ribbon 的功能
- 部分纳入范围：共享逻辑层和宿主抽象层中已被主插件调用的能力

## 3. 目标用户

- 规范类文档编写人员
- 需求、系统、设计、测试文档维护人员
- 文档审查与标准化执行人员
- 需要批量整理同类文档的项目成员

### 4.2 引导式规范分层

本插件的功能分层不按代码模块划分，而按“软件人员拿到一份文档后的处理顺序”划分。

| 层级 | 层级名称 | 核心目标 | 典型功能 |
|---|---|---|---|
| L1 | 建档与上下文层 | 先把文档纳入可管理、可识别、可定位的状态 | 文档组、基本信息、书签窗格、标识窗格 |
| L2 | 结构统一层 | 先处理确定性强、争议小的基础规范项 | 常用样式库、自动章节号、总页码、页面间空白 |
| L3 | 对象规范层 | 再处理表格、图片、题注等版面对象 | 表格选取、图表规范、续表拆分/合并、设置为表头、题注刷新、题注引用、表格自动序号 |
| L4 | 内容复用层 | 在结构稳定后再做跨文档内容搬运与批处理 | 批量替换、智能匹配 |
| L5 | 审查与追踪层 | 做标识核对、追踪关系建立和标准审查闭环 | 标识窗格、需求追踪、GJB438C 合规检查（规划） |

该分层体现的“引导式规范”原则如下：

- 先做确定性规范，再做判断性检查，减少反复返工
- 先处理单文档内部结构，再处理跨文档协同
- 先帮助用户把文档整理到“可检查”状态，再进入标准符合性检查

### 4.3 软件人员处理一份文档的推荐顺序

当软件人员拿到一份新文档时，推荐按以下顺序使用插件：

1. 先完成建档：将文档加入文档组，补充基本信息，确认文档归属和上下文。
2. 再完成结构统一：使用样式库、自动章节号、总页码等功能，把标题体系、页码字段和基础排版统一起来。
3. 再处理图表对象：定位并规范表格、图片、续表和题注，保证版面对象满足统一格式要求。
4. 再做内容加工：当结构已经稳定后，再使用批量替换和智能匹配，避免前面未定型导致的大量返工。
5. 再做追踪与核查：通过标识窗格检查关键标识，再用需求追踪功能建立关系并生成追踪表。
6. 最后进入标准审查：后续接入 GJB438C 合规检查后，再基于已规范化的文档执行条目检查、问题定位和整改复验。

这样设计的目标不是一次性把所有规则压给用户，而是让插件逐步引导用户从“能写”进入“写规范”，再进入“可审查、可交付”。

## 5. 详细功能需求

### 5.1 批量功能

#### 5.1.1 文档组管理

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| FR-DG-01 | 系统应支持创建、重命名、删除文档组。 | 用户可在“文档组管理”中完成组的新增、改名和删除。 |
| FR-DG-02 | 系统应保证任意时刻至少存在一个“活动文档组”概念；当用户未手工指定活动组时，应优先使用当前文档所在组，否则回退到首个文档组。 | 文档组菜单始终能解析出当前活动组，且“当前文档添加到组”有明确目标。 |
| FR-DG-03 | 系统应支持将当前活动文档快速加入活动组；当不存在任何文档组时，应先引导创建新组，再将当前文档加入。 | 点击“当前文档添加到组”后，文档被加入指定组，并给出结果提示。 |
| FR-DG-04 | 系统应支持在管理窗口内维护组内文档，包括添加文件、移除文件、移动到其他组、打开文档、清理失效路径。 | 管理窗口内可完成组内文档的基本维护操作。 |
| FR-DG-05 | 文档组数据应持久化保存到本机用户目录。 | 关闭并重新打开 Word 后，文档组及活动组状态仍可恢复。 |

补充说明：

- 文档组数据当前保存在 `%AppData%\DocuLint\document-groups.xml`
- 当前文档必须已经保存到磁盘后，才能加入文档组

#### 5.1.2 文档基本信息

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| FR-DI-01 | 系统应提供“基本信息”窗口，展示当前文档已保存的基础信息项。 | 打开窗口后能看到已有字段列表；无数据时显示“当前没有基本信息”。 |
| FR-DI-02 | 系统应支持对基础信息项进行新增、修改、删除。 | 用户可维护“名称-内容”型字段集合。 |

| FR-DI-04 | 系统应兼容既有字段镜像，至少包括“产品标识、产品名称、需求前缀、代码行数”。 | 老文档中的既有字段可被读取，新文档保存后仍同步维护上述镜像字段。 |

- 当前实现通过 Word Custom Document Properties 持久化
- 完整字段集通过 `DocuLint_BasicInfoPayload` 保存，兼容字段通过单独属性镜像保存

#### 5.1.3 智能匹配

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| FR-SM-01 | 系统应以“当前活动文档”为源文档，以“活动文档组”中的文档为候选目标，提供章节内容同步能力。 | 打开“智能匹配”后，界面展示活动组文档视图，并标识已匹配到的文档。 |
| FR-SM-02 | 系统应预置固定文档类型视图，至少包括 SDP、STP、SSS、SRS、SDD、STD、STR、SPS、SVD、SUM、FAM、SSR。 | 活动组中存在对应文件时，卡片高亮并可点击打开。 |
| FR-SM-03 | 系统应允许用户选择要替换的章节范围，当前版本至少支持“系统功能、软件功能、项目的相关机构”。 | 用户勾选章节后可执行替换。 |
| FR-SM-04 | 系统应根据章节标题匹配源文档和目标文档中的同名章节，并将源章节正文格式化内容整体覆盖到目标章节正文。 | 目标文档中对应章节正文被替换，章节标题本身保留。 |
| FR-SM-05 | 系统应在处理结束后输出成功数、失败数、失败明细和章节替换次数。 | 执行结束后弹出汇总信息。 |

补充说明：

- 章节定位当前同时兼容“标题样式”和“编号标题文本”两种识别方式
- 当前目标文档匹配主要依赖活动组中文件名与预置关键字的对应关系

### 5.3 图表处理

#### 5.3.1 表格选取与定位

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| FR-TB-01 | 系统应支持“全部表格”选择，优先从目录之后开始扫描；当文档没有目录时，处理全文表格。 | 点击后仅选中表格范围，不应混入周边正文。 |
| FR-TB-02 | 系统应支持基于当前光标定位“下个跨页表格”。 | 光标后存在跨页表时，点击后该表被选中；不存在时给出提示。 |
| FR-TB-03 | 系统应支持基于当前光标定位“下个续表”。 | 光标后存在续表时，点击后该表被选中；不存在时给出提示。 |

#### 5.3.2 图表规范

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| FR-TF-01 | 系统应支持“规范所有表格”和“规范选中的表格”两种入口。 | 用户可分别对全文表格或当前选中表格执行统一规范。 |
| FR-TF-02 | 系统应支持配置表格规范参数，至少包括表头字体、表头字号、正文字体、正文字号、表格宽度、外框线宽度、内框线宽度。 | 规范参数可在设置窗口中查看和修改。 |
| FR-TF-03 | 系统应支持“规范全部图片”，统一图片段落格式，并按配置缩放图片。 | 主文档中的图片被统一设置为居中、单倍行距、缩进为 0，并按 50%/75%/100% 缩放。 |
| FR-TF-04 | 系统对图片规范化时应跳过首页图片。 | 首页图片不参与“规范全部图片”的批处理。 |

补充说明：

- 表格默认参数：表头黑体 12 磅、正文宋体 10.5 磅、表宽 17.4 cm、外框线 1.5 磅、内框线 0.5 磅
- 图片默认缩放比例为 100%

#### 5.3.3 续表拆分、表头指定与续表合并

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| FR-CT-01 | 系统应支持对跨页表格执行“按续表拆分”。 | 对跨页表执行后，原表按分页位置拆成正表与续表。 |
| FR-CT-02 | 系统在拆分续表时，应补齐续表表头，并在续表前插入“表N（续）”题注。 | 拆分完成后续表具备表头和续表题注。 |
| FR-CT-03 | 系统应支持用户手工指定表头行数，且手工指定结果优先于自动识别。 | 选中表头区域后点击“设置为表头”，后续拆分和合并均按该行数处理。 |
| FR-CT-04 | 系统应支持“合并续表”，且允许从正表或续表任一入口触发。 | 当光标在正表或续表中时，只要两表满足续表关系，即可完成合并。 |
| FR-CT-05 | 系统在合并续表时，应删除续表前的续表题注，并去除续表头部重复表头后再合并内容。 | 合并后不残留“表N（续）”段落，也不保留重复表头。 |

### 5.4 题注处理

#### 5.4.1 题注刷新

| 编号 | 需求说明 | 验收标准 |
|---|---|---|
| FR-CP-01 | 系统应支持“更新图片题注”，从目录之后开始扫描文中图片，并按顺序刷新为“图1、图2、图3……”格式。 | 图片后的题注被重编号，原有说明文字后缀尽量保留。 |
| FR-CP-02 | 系统应支持“更新表格题注”，从目录之后开始扫描文中表格，并按顺序刷新为“表1、表2、表3……”格式。 | 表格前的题注被重编号，原有说明文字后缀尽量保留。 |
| FR-CP-03 | 系统处理续表题注时，应保持与正表相同的主编号，并显示为“表N（续）”。 | 续表不应额外占用新编号。 |
| FR-CP-04 | 系统刷新题注时，应自动维护题注引用所依赖的书签和域。 | 刷新题注后，相关引用可继续更新。 |

| 编号 | 需求说明 | 验收标准 |
|---|---|---|

### 5.8 GJB438C 合规检查（规划）

本节为后续规划功能，用于约束未来“文档是否符合 GJB438C”检查能力的产品形态，不代表当前版本已经实现。

| 编号 | 需求说明 | 规划验收标准 |
|---|---|---|
| FR-GJB-01 | 系统应支持按文档类型加载对应的 GJB438C 检查规则集。 | 用户可针对需求、设计、测试等不同类型文档执行匹配的检查项。 |
| FR-GJB-02 | 系统应支持对文档基础信息完整性、章节结构、样式格式、图表题注、标识与追踪相关内容进行规则化检查。 | 检查结果至少覆盖元数据、结构、对象、标识、追踪五类问题。 |
| FR-GJB-03 | 系统应支持对检查结果分级，至少区分“严重不符合、一般不符合、待确认、优化建议”。 | 检查结果列表中能够区分问题优先级，便于用户先处理硬性问题。 |
| FR-GJB-04 | 系统应支持对每个问题给出定位信息，并可一键跳转到对应段落、表格、题注或标识位置。 | 用户可从问题列表直接跳回文档定位点。 |
| FR-GJB-05 | 系统应支持将部分问题与现有规范化功能联动，形成引导式整改路径。 | 例如结构问题可引导到样式/章节号功能，图表问题可引导到图表规范或题注刷新功能。 |
| FR-GJB-06 | 系统应支持在整改后重新执行检查，并更新问题状态。 | 同一文档修正后可复检，已解决和未解决问题能够区分。 |
| FR-GJB-07 | 系统应支持输出检查摘要和问题明细报告。 | 用户可得到可用于评审或交付的检查报告。 |
| FR-GJB-08 | 系统应避免把标准检查设计成一次性静态列表，而应按处理阶段逐步暴露问题。 | 用户先看到建档和结构类问题，随后再进入对象类、追踪类和综合类问题。 |

## 6. 数据与配置要求

| 编号 | 要求说明 |
|---|---|
| DR-01 | 文档组信息持久化到 `%AppData%\DocuLint\document-groups.xml`。 |
| DR-02 | 文档基本信息持久化到 Word 文档自定义属性中。 |
| DR-03 | 自动序号方向保存到用户级设置 `QuickToolsAutoNumberDirection`。 |
| DR-04 | 图表规范参数在当前插件运行期内可复用，并由设置窗口统一维护。 |
| DR-05 | 后续 GJB438C 检查规则应支持按标准版本、文档类型和检查项类别进行配置与扩展。 |

## 7. 非功能要求

| 编号 | 需求说明 |
|---|---|
| NFR-01 | 长耗时操作应提供过程反馈，当前至少包括跨页表拆分、表格规范、图片规范、章节号重建。 |
| NFR-02 | 大部分功能在执行前应校验是否存在活动文档、是否存在有效光标或选区，并在不满足前置条件时给出明确提示。 |
| NFR-03 | 批处理类操作发生部分失败时，不应直接中断整体汇总；系统应保留成功结果并输出失败明细。 |
| NFR-04 | 插件应保证 Word 文档对象模型下的可用性与稳定性，当前版本仅面向 Word 运行环境。 |
| NFR-05 | 后续 GJB438C 合规检查应强调“引导式规范”体验，避免一次性抛出过多无优先级的问题，影响用户整改效率。 |

## 8. 当前版本边界说明

- 当前需求说明以已落地功能为准，不包含旧文档中曾出现但当前 Ribbon 已无入口的能力
- 智能匹配当前只覆盖 3 个章节主题：`系统功能`、`软件功能`、`项目的相关机构`
- 需求追踪当前依赖“文档已在当前 Word 会话中打开”，不支持直接从磁盘离线加载
- 图表、题注、标识等扫描型功能普遍采用“目录后开始处理”的规则
- GJB438C 合规检查当前仅作为规划项写入本说明书，尚未形成 Ribbon 入口和运行态能力

## 9. 建议的验收顺序

1. 先验收 Ribbon 入口完整性和窗口可打开性
2. 再验收文档组、基本信息、智能匹配等业务流程功能
3. 再验收图表、题注、章节号、自动序号等文档内容改写功能
4. 再验收导航窗格与需求追踪等组合能力
5. 如后续纳入 GJB438C 合规检查，再单独验收规则装载、问题分级、定位跳转、整改复检和报告输出链路
